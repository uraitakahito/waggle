## What waggle is

waggle answers one question: **which URLs get captured**. A caller asks for a
crawl; waggle works out the seeds — an explicit list, or the enabled rows of a
Postgres `capture_targets` table — decides what is in scope, and hands one level
at a time to a Windmill flow that does the submitting.

The name comes from the [waggle dance](https://en.wikipedia.org/wiki/Waggle_dance)
bees use to point hive-mates at nectar.

## What is not waggle's responsibility

Driving a browser, taking screenshots, building a WACZ, writing to S3 — every
one of those is **BrowserHive's responsibility**. BrowserHive's docs are not
published on the web — build them from the BrowserHive checkout with
`pnpm run docs:local`.

**Submitting is not waggle's either, any more.** The Windmill flow in
[capture-scheduler](https://github.com/uraitakahito/capture-scheduler) holds the gRPC channel, and
waggle has no BrowserHive address in its configuration at all. Each level the
flow reports comes back with a `taskId` per page, and waggle registers what
produced an archive in the [archive ledger](/waggle/archive-ledger/). Anything
missed is picked up later by `pnpm run fga:reconcile`, which sweeps the bucket's
result manifests.

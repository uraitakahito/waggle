## What waggle is

waggle answers one question: **which URLs get captured**. It selects the enabled
rows of a Postgres `urls` table and submits one `SubmitCapture` call per row to a
BrowserHive server, in parallel.

The name comes from the [waggle dance](https://en.wikipedia.org/wiki/Waggle_dance)
bees use to point hive-mates at nectar.

## What is not waggle's responsibility

Driving a browser, taking screenshots, building a WACZ, writing to S3 — every
one of those is **BrowserHive's responsibility**. BrowserHive's docs are not
published on the web — build them from the BrowserHive checkout with
`pnpm run docs:local`.

The submission itself is asynchronous: `SubmitCapture` returns a `taskId`
immediately and the capture runs on BrowserHive's worker pool. waggle then waits
for each accepted capture and records the ones that produced an archive in the
[archive ledger](/waggle/archive-ledger/). `--no-collect` submits and exits
instead; whatever is missed is picked up later by `waggle-ledger reconcile`,
which sweeps the bucket's result manifests.
